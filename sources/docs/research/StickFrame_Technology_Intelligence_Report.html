1. Executive Summary

This report maps the open-source ecosystem for building StickFrame — a text-to-stickman-animation engine. The goal is to identify libraries, repos, and skills that reduce the amount of code Claude Code and Codex need to write from scratch.

Key Finding: You can save ~60% of boilerplate code by leveraging existing libraries. The core unique value (stickman rig + animation data model) must still be built from scratch.

3. Recommended Architecture (Based on Research)

Recommendation: Use Pillow + pytweening for the MVP (simplest path), evaluate movis for the production pipeline. Do NOT use game engines (pygame/arcade) — they're designed for interactivity, not headless frame rendering.

Option A: Pillow + pytweening (MVP — Recommended)

  sources/engine/
  ├── scene.py              # Scene data models (Pydantic)
  ├── animation.py          # AnimationPlayer + keyframe interpolation
  ├── animation_clips.py    # Walk/run/jump/attack/fall keyframe data
  ├── rig.py                # Stickman skeleton joint resolver
  ├── renderer.py           # Pillow-based frame renderer
  ├── ffmpeg_export.py      # PNG sequence → ffmpeg → MP4
  ├── __main__.py           # CLI entry point
  └── demo_scene.json       # Test scene

Dependencies: pip install pillow pytweening + ffmpeg on PATH

Option B: movis Pipeline (Production — Strong Candidate)

  sources/engine/
  ├── scene.py              # Scene data models
  ├── animation.py          # AnimationPlayer
  ├── animation_clips.py    # Keyframe data
  ├── rig.py                # Skeleton joint resolver
  ├── layers.py             # Movis-compatible custom layers (stickman drawing)
  └── __main__.py           # Builds movis Composition + adds layers → write_video()

Dependencies: pip install movis pytweening

⚠️ movis Risk: Last commit was 2 years ago (2024). The repo may be unmaintained. Test compatibility with Python 3.13 before committing to this path.

3.1 Stickman Skeleton Model (Based on The-StickMan + Axis Research)

Based on analysis of existing stickman frameworks, our joint hierarchy should be:

  HEAD (center)                    # Circle
    │
  BODY_TOP (neck/shoulders)        # Origin for arms
    │
  BODY_BOTTOM (hips)               # Origin for legs
  
  LEFT_SHOULDER ── LEFT_ELBOW ── LEFT_HAND    # Upper arm → forearm → hand
  RIGHT_SHOULDER ── RIGHT_ELBOW ── RIGHT_HAND
  LEFT_HIP ── LEFT_KNEE ── LEFT_FOOT          # Thigh → shin → foot
  RIGHT_HIP ── RIGHT_KNEE ── RIGHT_FOOT

Each limb has a base angle + animation angle offset, as demonstrated in The-StickMan's RotateableLine class.

3.2 Keyframe Data Format (Based on Axis + Research)

Similar to Axis's approach but simpler — per-frame joint angle arrays with linear interpolation:

  AnimationClip "walk":
    Frame 0: { left_arm: 30, right_arm: -30, left_leg: -25, right_leg: 25, body_tilt: 3 }
    Frame 2: { left_arm: 0,  right_arm: 0,   left_leg: 0,   right_leg: 0,  body_tilt: 0 }
    Frame 4: { left_arm: -30, right_arm: 30,  left_leg: 25,  right_leg: -25, body_tilt: -3 }
    Frame 6: { left_arm: 0,  right_arm: 0,   left_leg: 0,   right_leg: 0,  body_tilt: 0 }
    Interpolation: linear (or use pytweening.easeInOutSine for smoother motion)

7. Engineering Recommendations

For Claude Code (Engineering Lead)

  • Use pytweening for all easing/tweening — pip install pytweening, import and done. 0 effort.
  • Reference The-StickMan/stickman.py for joint rotation math (RotateableLine class)
  • Reference Axis for keyframe animation approach
  • Install claudedesignskills — load animation/graphics skills
  • Study Stickman-Studio pipeline for architecture inspiration (not code reuse)

For Codex CLI (Core Engine Lead)

  • Evaluate movis as a potential rendering backend — test with Python 3.13
  • Use Pillow + subprocess ffmpeg as the safe default
  • Install motion-skills for motion graphics patterns
  • Reference Stickman-Studio/ffmpeg stitching for video export code
  • Keep it simple — the rendering loop is: draw frame → save PNG → ffmpeg stitch

Where We Must Build From Scratch

Unique code that has no existing library to copy from:
  1. Scene data model (Scene, Character, Camera, Timeline) — custom to StickFrame
  2. Stickman animation keyframes (walk/run/jump/attack/fall data) — custom authored
  3. Script-to-scene parser (text input → structured scene commands) — unique to StickFrame
  4. Action timeline system (character:hero:walk at t=2.0) — custom DSL
Everything else can leverage existing open-source libraries.
